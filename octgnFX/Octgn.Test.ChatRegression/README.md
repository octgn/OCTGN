# Chat handler regression checks

Restore the repository's `octgnFX/Octgn.Test/packages.config` dependencies into the root `packages` directory, for example with `nuget restore octgnFX/Octgn.Test/packages.config -PackagesDirectory packages`. This supplies NUnit 3.13.3 and NUnit.ConsoleRunner 3.20.1. Build on Windows with `msbuild octgnFX/Octgn.Test.ChatRegression/Octgn.Test.ChatRegression.csproj /p:Configuration=Release /m:1 /nr:false`, then run `packages/NUnit.ConsoleRunner.3.20.1/tools/nunit3-console.exe octgnFX/Octgn.Test.ChatRegression/bin/Release/Octgn.Test.ChatRegression.dll --workers=0 --agents=1 --process=Single --timeout=10000`. The project targets .NET Framework 4.8 and has an entry in OCTGN.sln. Validation used the standalone project command with isolated output paths; compilation through the complete solution was not verified. `NUnitFrameworkPath` can point to an existing restored assembly in another checkout. No CI execution is claimed.

It compiles the production handler, broadcaster, binary parser, context/state, configuration, player settings and API message model directly. Test doubles replace socket players, timers, localization, logging and unrelated hosting/API dependencies. This verifies chat opcode dispatch, exact sender/payload (Unicode, empty and direct-call null), mute behavior for local/hosted games, production Broadcaster connected-recipient filtering, and exception propagation. Registration filtering is represented by a double matching PlayerCollection.Players, not real registration/lifecycle integration. Unexpected API calls throw. Packet header 42 is a test value for BinaryParser's IsMuted field; opcode 21 is ChatReq in the existing generated BinaryParser/Protocol.xml.

`HandlerSource` can select an earlier version of Handler.cs to run the same checks against a baseline. These checks cover chat control flow; they do not replace the legacy .NET Framework solution build, transport serialization tests, or real socket integration.
